## Update 16:40-17:05: two real breaks the first offline check could not see
The 15:xx runs below all passed. The check had two blind spots: it handed the SDK a ready-made HTTP
client, and its fake server accepted any request. Closing them found two breaks in the 24-10 fix.

1. **SDK 2.x sends API version 2026-10-21, which rejects `temperature` on every model.** Probed from the
   installed SDKs: 1.17.0 sends `anthropic-version: 2023-06-01`, 2.12.0 sends `2026-10-21` (Anthropic's
   API-version guide: Python SDK 2.0.0 is the first to send it; on that version `temperature`, `top_p`
   and `top_k` are a 400 on every model, even via `extra_body`). `<3` resolves to 2.12.0 today, so a
   fresh install made every Claude call to a model that takes temperature fail. That is Claude 3.x and
   4.0-4.6, e.g. Haiku 4.5 and Sonnet 4.6, text and vision. The default Opus 4.8 route was not affected
   (temperature was already omitted there).
2. **SDK below 0.40 crashes with httpx 0.28** when it builds its default client (`TypeError:
   AsyncClient.__init__() got an unexpected keyword argument 'proxies'`). The app builds its client
   that way, and `httpx>=0.27.0` resolves to 0.28.1 today. 0.40.0 works. The floor `0.39.0` was
   therefore wrong.

**Fix:**
- `backend/app/providers/text_client.py`: temperature is sent (via `extra_body`) only when the client's
  `anthropic-version` is `2023-06-01` AND the model takes it (`_anthropic_sends_temperature`). An
  unknown version is treated as new. Otherwise the call runs at the model's default sampling. The
  comment says why, and a debug log line records each omission.
- Both requirements files: `anthropic>=0.40.0,<3`.

PICKED: keep temperature 0.2 where the API still takes it (SDK <2) and run at default sampling on
2026-10-21, not a `<2` cap or a version override. Why: the `<2` cap holds every call back on the old
API version, and an override is the guide's least-recommended route. The app's default Claude route
(Opus 4.8) already ran at default sampling, so only user-picked Claude 3.x-4.6 models change. This
matches the guide's recommended choice 1 ("delete the setting").

**Guard (the test now catches this kind of fault, not only these two cases):** `backend/tests/test_anthropic_sdk_compat.py`
fakes only the network layer (the httpx/httpx2 transport), so the SDK builds its own client. Its fake
server enforces the API rules by the `anthropic-version` header the SDK actually sends (sampling
settings on a version other than 2023-06-01 → 400; temperature to a default-sampling-only model → 400),
and it has 4 new direct cases for the version rule. 22 checks (was 18). `check_task_management.py`
fakes the network the same way and builds the client like that app does.
